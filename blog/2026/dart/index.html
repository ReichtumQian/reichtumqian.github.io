DART: Decoded Attention over Recurrent States

Created on September 10, 2026

2026

Long documents often ask a language model to do two things at once: follow the evolving context and recover a specific detail mentioned much earlier. Recurrent models offer an efficient way to summarize context. Attention offers an explicit way to search it.

DART gives these two operations a shared memory representation. It extends Mamba-2 by retaining compressed memories of earlier chunks and decoding keys and values from those memories when a new token needs them. This post develops the idea from the memory trade-off to the equations, implementation, and experimental evidence.

Read the paper · Paper PDF

The memory trade-off

In a Transformer, token-level attention stores a key and a value for each preceding token. A new query can compare against these keys and retrieve a weighted combination of the values. This gives the model explicit access to individual positions, while the inference key–value cache grows with sequence length.

A recurrent model such as Mamba-2 continually updates a fixed-size state. Each new token contributes to this compressed representation of the past. The state is efficient to maintain, but many earlier associations must coexist in limited space. Recovering a particular name, number, or attribute can become difficult as information accumulates.

Consider a document containing several product names and serial numbers. Following the document’s topic requires a useful summary; answering a question about one product requires retrieving a particular association. These demands motivate a memory that supports both recurrent updates and selective retrieval.

A shared memory inside the block

An interleaved hybrid places recurrent layers and attention layers at different depths. Each component uses its own memory mechanism. DART integrates state-memory attention, abbreviated as SMA, into the Mamba-2 block. The recurrent computation supplies the compressed memories that SMA searches.

The starting point is the state space duality view of Mamba-2. For one head, a simplified recurrent update and readout are

\[\begin{aligned} H_t &= a_t H_{t-1} + B_t^\top X_t, \\ Y_t^{\mathrm{SSM}} &= C_t H_t. \end{aligned}\]

Here \(H_t\in\mathbb{R}^{N\times P}\) has a key axis of size \(N\) and a value axis of size \(P\). The outer product \(B_t^\top X_t\) writes an association into the state, the scalar \(a_t\) controls how the preceding state carries forward, and the row vector \(C_t\) reads a value from it. These equations isolate the state operation; the full block also contains projections, a convolution, normalization, and gating.

This matrix can be understood as a compressed associative key–value memory. Mamba-2 already reads it along the key axis to produce values. DART adds a complementary read along the value axis to produce keys for attention.

From chunk contributions to stored memories

Mamba-2’s chunkwise computation divides a sequence into chunks of \(S\) tokens. Alongside local outputs, it computes each chunk’s contribution to the recurrent state. For chunk \(c\), ending at position \(e(c)\), that contribution is

\[\Delta H_{[c]} = \sum_{s\in[c]} \left(\prod_{k=s+1}^{e(c)} a_k\right) B_s^\top X_s.\]

The product accounts for the decay between a token and the end of its chunk; an empty product equals one. Each matrix \(\Delta H_{[c]}\in\mathbb{R}^{N\times P}\) summarizes the associations written within that chunk. The cumulative boundary state also contains contributions from earlier chunks, so these two tensors have different meanings.

DART retains the individual contribution matrices as chunk state memories. The native recurrent state continues to evolve, while SMA gains access to a sequence of compressed historical memories. Retaining them avoids making all retrieval depend on the latest accumulated state.

This design reuses tensors produced by the existing computation. Keeping those tensors for later retrieval adds storage, and reading them adds computation. DART’s historical cache therefore grows with the number of chunks.

Decoding keys and values for the current token

For a token at position \(t\), the block input \(U_t\) produces three vectors:

\[\begin{aligned} Q_t &= U_t W_Q, \\ C_t &= U_t W_C, \\ E_t &= (U_t W_E)^\top. \end{aligned}\]

The query \(Q_t\in\mathbb{R}^{1\times N}\) determines which chunk memories receive attention. The native Mamba-2 read vector \(C_t\in\mathbb{R}^{1\times N}\) extracts values. The verifier \(E_t\in\mathbb{R}^{P\times 1}\) reads the value axis to construct a key for each memory.

For a historical chunk \(c\), the two decoded representations are

\[\begin{aligned} V_{t,c} &= C_t\Delta H_{[c]} \in\mathbb{R}^{1\times P}, \\ K_{t,c} &= \Delta H_{[c]}E_t \in\mathbb{R}^{N\times 1}. \end{aligned}\]

The stored object is a matrix; its decoded key and value depend on the current token. The same chunk memory can yield different representations at different positions. Both readouts are token-conditioned through \(C_t\) and \(E_t\), with a separate query \(Q_t\) used to score the decoded key.

The attention calculation then has a familiar form:

\[\begin{aligned} \ell_{t,c} &= \frac{Q_t K_{t,c}}{\sqrt{N}}, \\ g_{t,c} &= \operatorname{softmax}_{c<c(t)}(\ell_{t,c}), \\ R_t &= \sum_{c<c(t)} g_{t,c}V_{t,c}. \end{aligned}\]

Here \(c(t)=\lceil t/S\rceil\) is the current chunk. SMA attends only to completed earlier chunks, preserving causality. The native recurrent branch handles the current chunk causally. For the first chunk, the historical memory set is empty and \(R_t=0\).

For clarity, these equations omit normalization in the score computation. The implementation applies RMS normalization to \(Q_t\) and \(E_t\), and scales the state rows by their inverse root mean square when decoding keys. Values retain the readout \(C_t\Delta H_{[c]}\). This controls the scale of routing scores without storing a separate normalized copy of every state.

Sharing the read vector

SMA uses the same \(C_t\) as the recurrent readout. A useful interpretation is that both branches learn to read the same representation of an association, whether it resides in the current recurrent state or in a historical chunk memory.

The paper tests this choice by training otherwise matched variants with an independent SMA value-read projection. In the memory-constrained multi-query associative recall experiment with \(N=16\), those variants remain at zero recall accuracy, while the shared-read variants succeed across the tested widths and lengths. This supports the shared design in that experimental setting; it does not establish that every independently parameterized alternative must fail.

Adding the retrieved information

The retrieved value enters as a gated correction to the native state readout:

\[\begin{aligned} G_t &= \operatorname{SiLU}(U_t W_G), \\ Y_t &= C_tH_t + G_tR_t. \end{aligned}\]

The gate \(G_t\) is scalar, and \(W_G\) is initialized to zero. The retrieval contribution therefore starts at zero and is learned during training. The surrounding Mamba-2 block processes the combined readout through its usual output operations.

Making retrieval efficient

The implementation has two complementary parts. First, Mamba-2’s chunkwise state space duality algorithm produces the recurrent outputs and chunk contributions together. Second, a custom FlashAttention-style kernel performs retrieval over those memories.

The kernel processes a tile of queries while streaming through historical chunk matrices. It decodes their keys and values in on-chip memory, updates an online softmax, and accumulates the retrieved output. Decoded keys, values, logits, and attention weights remain temporary quantities. The forward pass writes the readout and log-sum-exp statistics to device memory; backward computation reconstructs the temporary quantities as needed.

This avoids materializing large token-by-chunk intermediate tensors. It reduces memory traffic while retaining the additional arithmetic required by SMA.

Cache size

Let the sequence length be \(L\) and the number of chunks be \(M=\lceil L/S\rceil\). A matched token-level attention head with key and value dimension \(P\) stores approximately \(2LP\) elements. DART’s historical chunk matrices require approximately \(MNP\) elements. Their leading, length-dependent cache ratio is

\[\frac{MNP}{2LP} \approx \frac{N}{2S}.\]

At \(N=128\) and \(S=256\), the ratio is \(1/4\): 75% less length-dependent cache under this matched comparison. For example, at \(L=4096\) and \(P=64\), the chunk matrices contain 131,072 elements per head, compared with 524,288 elements for token keys and values.

This comparison assumes the same element precision and excludes fixed recurrent state, small normalization statistics, model weights, and other runtime allocations. It describes the dominant historical cache term. Total device-memory savings depend on the complete implementation and the attention baseline’s head-sharing configuration.

Compute cost

Each token can visit roughly \(L/S\) historical chunks, with key and value decoding costing \(O(NP)\) per visit. The added SMA computation is

\[O(LMNP)=O\!\left(\frac{L^2NP}{S}\right).\]

For fixed \(N\) and \(S\), this is quadratic in sequence length, on top of Mamba-2’s linear-time state computation. Relative to token-level attention’s \(O(L^2P)\) arithmetic, the leading ratio is \(N/S\). Actual latency also depends on kernel utilization and memory movement; this ratio alone gives no wall-clock speedup guarantee.

Smaller chunks preserve more separately addressable memories and increase retrieval work. Larger chunks reduce cache and computation while compressing more information into each memory. Chunk size controls this trade-off.

What the experiments show

Associative recall

Multi-query associative recall, or MQAR, asks a model to remember several key–value pairs and predict the associated value when a key reappears. The paper compares DART and Mamba-2 at matched model widths and state sizes, alongside a Transformer++ baseline.

At \(N=64\), DART reaches near-perfect recall across all tested widths and sequence lengths. Even with \(N=16\), it exceeds Mamba-2 with \(N=64\) at matched widths in these experiments. The gains suggest that selective access to stored states can make compressed associations more useful.

The chunk size here is \(S=16\). The separate 75% cache-saving example uses \(S=256\) and \(N=128\); that percentage should not be assigned to this MQAR setting.

Language modeling and extraction

The language models are pretrained on the Pile for 100 billion tokens. DART adds fewer than 3% parameters to the corresponding Mamba-2 backbones. The main language-modeling configuration uses \(S=256\) and \(N=128\).

Model pair, Mamba-2 → DART Pile perplexity ↓ Average zero-shot accuracy ↑
130M → 133M 12.23 → 12.13 39.96% → 40.65%
370M → 380M 9.99 → 9.90 44.08% → 44.40%
780M → 795M 8.85 → 8.86 46.93% → 47.53%

The average covers seven downstream accuracy metrics reported in the paper. General language-modeling quality stays close to the backbone, with modest average downstream gains. Most examples in these downstream benchmarks are shorter than 256 tokens, so many do not activate historical-chunk retrieval at this chunk size. This evaluation primarily checks that training with SMA preserves the recurrent branch’s general capability.

The changes are larger on information extraction. SWDE asks for attribute values from web pages; FDA asks for values associated with requested keys in regulatory documents. Both are scored with contains accuracy, which checks whether the generated response contains the expected answer.

Model pair, Mamba-2 → DART SWDE ↑ FDA ↑
130M → 133M 17.1% → 34.9% 15.4% → 19.7%
370M → 380M 33.2% → 46.9% 16.6% → 31.3%
780M → 795M 39.9% → 56.5% 17.2% → 28.9%

These entries use DART’s main \(S=256\) setting. Synthetic needle-in-a-haystack tests also show substantial gains in several configurations: for example, on NIAH-Single-2 at 2,048 tokens, the 780M/795M comparison improves from 24.6% to 70.0%.

The results vary by task and context length. Many 4,096-token NIAH-Single-2 and Single-3 settings remain difficult. There are regressions as well: on NIAH-Single-1 at 4,096 tokens, DART 133M scores 57.2% versus Mamba-2 130M’s 74.2%. Full-attention Pythia remains stronger on several extraction and question-answering metrics, and Attamba is strong on several synthetic retrieval settings. The paper’s complete tables provide the broader comparison behind the selected results above.

Implications and open questions

DART separates two uses of recurrent memory: updating a running summary and retrieving from individual compressed contributions. A chunk state matrix supports both operations, with token-conditioned reads turning stored states into keys and values when needed.

The evidence supports improved associative recall and extraction with a smaller historical cache than matched token-level attention in the reported configuration. The remaining questions concern how this trade-off changes with longer contexts, larger models, different chunk sizes, and tasks requiring exact details that compression may discard. DART provides a concrete architecture for studying shared recurrent memory and attention-style retrieval together.
